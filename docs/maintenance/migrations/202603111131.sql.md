## RAGFlow metadata and shadow document table

The first comment adds fields returned by RAGFlow when creating/querying a knowledge base. Dynamic-DDL annotations mean: `tenant_id` = tenant ID; `avatar` = knowledge-base avatar (Base64); `embedding_model` = embedding model name; `permission` = permission setting `me/team`; `chunk_method` = chunking method; `parser_config` = parser configuration (JSON); `chunk_count` = total chunks; `document_count` = total documents; `token_num` = total token count. Each guard checks whether the column exists before adding it.

The next comments introduce the shadow document table for RAGFlow. It retains a document-ID association between the remote RAGFlow ID and local ID as backup metadata; RAGFlow still stores the file contents. Read the complete schema translations below for document status, parsing progress/duration, storage source, counts, errors and timestamps. Preserve status enums and the `me/team` permission identifiers.
